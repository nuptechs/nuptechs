05Fluxo end-to-end · do SLA violado à glosa decidida

Caso real percorrendo as camadas. Demonstra como a arquitetura suporta o caso de uso central: detectar violação, reunir contexto, apoiar decisão, registrar ato, manter trilha.

# Evento O que o sistema faz Onde fica registrado
1 Aferição mensal de SLA Cron periódico chama serviço de aferição que calcula indicador (MTTR) por contrato; se > alvo, cria SlaMeasurement com flag violated=true SlaMeasurement + AuditLog (criação)
2 Motor de regras dispara Regra configurada "SLA violado → criar DecisionAdvice" dispara action executor; valida que contrato pertence ao órgão (multi-tenant); valida config da regra RuleExecution + AuditLog (rule fired)
3 Resolver de fundamentação roda Componente reúne: (a) cláusula contratual aplicável, (b) referências legais via base de conhecimento, (c) histórico de execução, (d) diretrizes vigentes do gestor (consulta semântica) DecisionAdvice.fundamentJson
4 Calculadora de opções gera escolhas Componente calcula impacto financeiro de cada opção (aplicar glosa via deflator do contrato, pedir esclarecimento, pedir entrega, notificar formalmente, arquivar) DecisionAdvice.optionsJson
5 Notificação ao gestor Motor de notificação envia in-app + e-mail + (opcional) WhatsApp conforme regra do órgão Notification + AuditLog (send)
6 Gestor abre o painel de decisão UI mostra fundamentação renderizada + opções clicáveis com impacto pré-calculado em R$ UI · sem mutation
7 Gestor decide Escolhe opção, redige motivação ≥ 100 caracteres (sustenta contraditório); confirma; sistema valida que gestor ≠ criador (segregação de funções) DecisionAdvice (status DECIDED) + AuditLog (decision)
8 Imutabilidade ativa Trigger PostgreSQL impede UPDATE nos campos de decisão; cadeia criptográfica encadeia o registro com o anterior PostgreSQL trigger + HMAC chain
9 Ato administrativo Conforme opção escolhida: cria FinancialEntry de glosa, ou envia notificação formal, ou cria HumanTask para fornecedor responder · sempre com link ao DecisionAdvice de origem FinancialEntry / Notification / HumanTask + AuditLog
10 Trilha exportável A qualquer momento, auditoria externa pode pedir exportação probatória do caso; sistema gera PDF com cadeia criptográfica e referência cruzada Export probatório · HMAC verificado

Air-gap (sem internet) suportado

Cliente que exige instalação totalmente isolada (ambiente sensível, regiões críticas) pode operar com modelo de IA hospedado localmente (Llama 3, Sabiá, Maritaca via Ollama/vLLM). Capacidades de IA disponíveis ficam reduzidas mas o sistema continua funcional. Sem dependência externa para a operação core (setup, execução, auditoria).

07Política de hospedagem de IA · onde os dados vão

Pergunta inevitável de DPO: "quando a plataforma chama o Claude, meus dados saem do Brasil?". Resposta clara abaixo.

Opção Onde processa Treino com seus dados? Quando faz sentido
Anthropic Claude direto EUA não (contrato API) órgão sem restrição geográfica · default da plataforma
Bedrock região SA (São Paulo) Brasil não órgão que exige residência de dados em território nacional
Bedrock região EU UE não conformidade GDPR explícita
Maritaca / Sabiá API Brasil não (contrato) preferência por fornecedor nacional · idioma português nativo
Self-hosted (Llama 3, etc.) seu data center N/A (você controla) air-gap · dados ultra-sensíveis · custo previsível

Garantia contratual padrão

Em todos os contratos de API que a NuPtechs mantém com provedores de IA, está explícito que os dados enviados não são usados para treinamento dos modelos do provedor. Cópia desses contratos disponível sob NDA para análise técnica.
