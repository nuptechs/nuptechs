01Cadeia cadeia criptográfica que detecta alteração · prova matemática reconstruível

Toda alteração em entidade auditável entra numa cadeia hash criptográfica encadeada. Mexer no banco quebra a cadeia. Reconciliação reconciliação exata entre serviços entre Java e Node garante consistência cross-service. Prova matemática verificável — vale em TCU, CGU, MPU, juízo.

ElementoImplementação verificada
Versão da cadeiaVersão 3 · sincronizada bit-a-bit entre serviço Java (serviço Java) e serviço Node (gateway + chat IA)
Genesis hashHash inicial determinístico, idêntico em todos os serviços, marca o início da cadeia por organização
AlgoritmoHMAC-SHA256 · chave secreta exclusiva da instalação · padrão criptográfico amplamente aceito (RFC 2104)
Input encadeadoHash do registro anterior + tipo da entidade + ID + ação + usuário + data ISO + delta das mudanças + organização · ordem fixa
Lock por organizaçãoBloqueio transacional dedicado por organização · previne escritas concorrentes que poderiam bifurcar a cadeia · idêntico em Java e Node
Captura universalListener Hibernate intercepta toda inserção, atualização e remoção de qualquer entidade auditável · sem decorator manual em cada classe
Falha em produçãoSem chave secreta configurada em produção, o sistema não sobe — fail-fast intencional · em desenvolvimento usa fallback explícito
Métricas de auditoriaContadores de sucesso e falha (com tag de causa) e tempo de escrita com percentis (mediana, p95, p99) expostos em formato Prometheus

O significado de "reconciliação exata entre serviços"

Java (serviço Java) e gateway de integração compartilham a mesma cadeia HMAC. Quando Chat IA cria um lançamento via tool sensível, o registro entra na cadeia com o mesmo algoritmo + advisory lock que o Spring usa. A integridade não é por serviço — é por organização. Pacote compartilhado: biblioteca compartilhada de auditoria.

02Compliance Engine em 3 camadas · custo escalonado

Validação por camadas: L1 determinística (rápida e barata), L2 com IA + RAG (quando precisa interpretação), L3 com comitê multi-LLM (quando severidade é bloqueante). Cada regra escolhe o motor adequado ao seu custo/qualidade.

L1 · Determinística

Analyzers locais paralelos no orquestrador de conformidade.java. Verificações regex, FEEL, scope check. Cria assessment status=COMPUTING, marca entregável (artefato).status=ANALYZING, executa lista de analyzers, agrega findings, marca COMPLETED ou FAILED. Resiliente: analyzer individual que falha não impede outros.

latência tipicamente <1s · custo ~$0

L2 · RAG + Claude

Modelo modelo de IA jurídico com busca semântica em índice semântico isolado por organização (até 8 trechos relevantes por consulta, no namespace da organização). A IA é forçada a usar uma função estruturada (status PASS/FAIL/INDETERMINATE + raciocínio ≤600 chars + lista de citações). Cada citação é validada contra os trechos retornados — citação que não bate vira INDETERMINATE auditável, não falsa aprovação.

latência ~2-5s · custo típico ~$0.030

L3 · Committee 3 LLMs

Três modelos votam em paralelo: modelo de IA jurídico + Claude Opus + modelo de IA alternativo. Decisão por maioria simples (basta 2 dos 3 concordarem). Cada modelo com falha individual retorna INDETERMINATE com motivo — o comitê tolera até 1 falha. Se não houver maioria, o sistema marca divergência e exige revisão humana. Custo somado típico: cerca de $0,10 por validação.

latência 5-15s · usado em regras bloqueantes

Sanitização e qualidade dos findings

Findings com achados com baixa confiança descartados são descartados automaticamente. Severity floor por categoria (CRITICAL/HIGH/MEDIUM/LOW). needs_human_review ativa quando confidence intermediária. Rate limit: 5 análises/min por usuário (custo Anthropic real). Cache content-addressable via buildRiskAnalysisCacheKey.

04Auditoria operacional · diff + trilha por entidade

A camada operacional registra "quem fez o quê, quando, sob qual estado". Diff antes/depois por campo, filtros multi-dimensionais, hash exportável como prova, visões segregadas por entidade.

visão consolidada por organização

05Auditoria técnica · análise automatizada de segurança do código + Análise de qualidade do código

A camada técnica audita o próprio código entregue pelo fornecedor. Análise automática de segurança (estática e dinâmica), métricas de qualidade, vulnerabilidades, complexidade ciclomática.

Achados de segurança do código integrados

Achados de segurança chegam via webhook assinado (HMAC-SHA256, validação timing-safe). Mapeamento automático entre projeto analisado e contrato em andamento. 4 status: aberto, diagnosticado, corrigido, verificado. Captura controlada por permissão dedicada.

tela dedicada · controlada por permissão

Análise de qualidade de código · 6 dimensões

Upload de pacote (ZIP, JS, TS, Java, Python, C#, Go). Análise via parser de árvore sintática. Saída: contagem de arquivos/funções/classes/linhas, code smells (críticos/maiores/menores), hotspots de complexidade, vulnerabilidades, cobertura de testes, tendências históricas. Opcional: relatório IA estruturado. Exportação JSON + CSV por severidade.

parser de árvore sintática + scoring multidimensional

06Auditoria jurídica · Compliance + Atesto Inteligente

A camada jurídica vincula tudo o que acontece a artigo/inciso da legislação aplicável. ComplianceFinding traz citation_literal + sourceArticle + sourceOffsetStart/End. Atesto Inteligente fundamenta parecer.

ComplianceCheckResult

validator_type_id (REGEX/RAG_LLM/COMMITTEE), validator_output (JSONB com chunk_id, citations, votos individuais do committee, reasoning), status (PASS/FAIL/INDETERMINATE/DISMISSED), denormaliza legal_obligation_id pra evitar JOIN.

defesa tribunal-ready

Triggers de imutabilidade

Gatilho no banco impede mutação de assessments concluídos (status COMPLETED ou FAILED). Decisões de finding (dismiss/resolve) também viram imutáveis após estado terminal — defesa em camada de dados, não só na aplicação.

imutabilidade no nível do banco

Compliance Copilot

Tela conversacional com RAG retrieval + LLM grounded. Pergunta livre → resposta com citations (chunk_id + text + article) + reasoning + actionsSuggested + latencyMs + model. Não inventa — sempre cita evidência.

09Exportação probatória · pra auditoria externa

Qualquer trilha pode ser exportada com identificadores de integridade. Como cada audit_log carrega hash + previous_hash determinísticos (HmacSHA256), qualquer ferramenta externa consegue recomputar e validar a cadeia. ComplianceFinding com evidence + citation literal é defensável em tribunal. Não é PDF gerado dinamicamente — é prova matemática reconstruível.

10Quem opera a Auditoria

Auditor interno

Acompanha AuditDashboard + ActivityHistory · investiga divergências · exporta trilhas pra TCU/CGU/MPU.

Comitê L3 Compliance

Revisa findings BLOCKING que caíram em COMMITTEE_DISSENT · assina parecer com fundamentação · two-eyes obrigatório.

CISO / SecOps

Monitora SentinelFindings + SecurityEvent · gerencia eventos rejeitados · responde a incidentes de segurança em tempo real.

Risk Officer

Analisa RiskAnalytics · revisa golden-set via RiskBenchmarkReview · ajusta playbooks por tipo de contrato.
