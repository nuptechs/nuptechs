Arcabouço legal vivo · não é PDF anexo, é entidade do domínio

Lei 14.133/2021, IN SGD/ME 94/2022, Decreto 11.246/2022, LGPD e os normativos próprios de cada contratante são modelados como entidades de dados: hierarquia normativa, versionamento temporal, aplicabilidade automática por critério, obrigações com motor de validação configurável, indexação RAG nativa. A IA não inventa — cita evidência. O fiscal não improvisa — segue a regra cadastrada.

01Modelagem do corpus legal · da Lei ao Inciso

O sistema modela cada norma como entidade com hierarquia, versionamento e aplicabilidade. Toda decisão aponta para a versão vigente no instante — não para a norma "raw". Permite reconstruir, anos depois, qual versão estava valendo quando o gestor decidiu.

EntidadePara que serve
LegalReferenceNorma raiz. Campos: code unique 50-char, name, referenceType (8 tipos), summary, content, sourceUrl, documentStorageKey, effectiveDate/expirationDate, isGlobal (true=público, false=org-specific), parent (Lei→Decreto→Portaria→IN), replacedBy (revogação em cascata)
LegalReferenceVersionSnapshot imutável de norma em ponto temporal · permite rastreabilidade ("qual versão foi consultada?")
LegalReferenceApplicability6 tipos de aplicabilidade automática + config JSONB + effectiveFrom/To
LegalObligationUnidade atômica de fiscalização · FK para legal_reference_version_id (nunca raw) · validatorType + obligationType + severity + appliesToEventTypes + appliesToEntityTypes + sourceExcerpt + sourceArticle + sourceOffsets
LegalObligationSuggestionSugestões extraídas por IA · workflow approval (PENDING → APPROVED · REJECTED)
LegalFrameworkRuleRegra estruturada do arcabouço como entidade configurável (não código). 5 tipos de regra (compliance, dispensa, prazo, documento exigido, benefício ME/EPP), configuração em JSON, indexação RAG opcional.

036 tipos de aplicabilidade automática · sem catálogo manual

Cada norma cadastrada declara quando ela se aplica. O sistema deduz automaticamente quais contratos estão sob qual norma — sem o fiscal precisar "marcar" manualmente em cada contrato.

Tipo de aplicabilidadeConfig JSONB exemplo
ALL(sem config) — aplica a todos os contratos da organização
BY_CONTRACT_TYPE{"contract_types": ["TIC"]} — só contratos de TI
BY_ORGAN{"organs": ["SGD/ME", "TCU"]} — só contratantes específicos
BY_CONTRACT_VALUE_RANGE{"min_value": 50000, "max_value": 1000000} — só faixa de valor
BY_LICITATION_MODALITY{"modalities": ["PREGAO_ELETRONICO", "DISPENSA"]}
BY_EXPRESSION{"expression": "contract.type == 'TIC' && contract.value >= 50000"} — FEEL custom

043 motores de validação · L1 / L2 / L3 escolhidos por regra

Cada obrigação (LegalObligation) declara seu motor de validação adequado. Não tudo precisa de IA: regra simples ("contém cláusula X?") roda determinística em ~5ms. Regra interpretativa pede LLM com RAG. Regra bloqueante chama comitê multi-LLM.

DETERMINISTIC · L1

Avaliação FEEL via Camunda FEEL Engine · regex · scope check. Latência ~5ms · custo ~$0. Para validações binárias diretas.

ValidatorType.DETERMINISTIC

RAG_LLM · L2

Claude Sonnet 4.5 + Pinecone TOP_K=8 + tool-use forçado · citação literal obrigatória · latência ~2-5s · custo ~$0.030. Para interpretação contextual.

ValidatorType.RAG_LLM

COMMITTEE · L3

3 LLMs em paralelo (Claude Sonnet + Claude Opus + Gemini Pro) com voto independente. Decisão por maioria simples (basta 2 dos 3 concordarem). Se não houver maioria, sinaliza divergência e exige revisão humana. Latência 5-15s · custo somado típico ~$0,10 por validação. Para regras bloqueantes.

ValidatorType.COMMITTEE

05RAG legal · Pinecone com 3 namespaces isolados

Toda norma indexada é vetorizada e armazenada em namespace dedicado em Pinecone (text-embedding-3-small ou Gemini text-embedding-004 via env var). Isolamento multi-tenant absoluto: diretrizes internas de um órgão jamais aparecem em consulta de outro.

NamespaceConteúdo
legal-publicLei 14.133/2021, LGPD, decretos federais, normativos federais aplicáveis — visível pra todas as organizações
legal-internal-<orgId>Normativos internos da organização específica · portarias do órgão
guidelines-<orgId>ManagerObservations (diretrizes do gestor) · isolado dos namespaces legais "oficiais"

06Acórdãos do TCU como entidade · não como nota de rodapé

O LegalReferenceType inclui contexto pra acórdãos TCU. Quando o TCU consolida orientação ("UST sem padronização é irregularidade"), o sistema cadastra como LegalReference + LegalObligation com validatorType adequado. As regras de validação derivadas passam a rodar automaticamente nos contratos novos.

Por que isso muda a régua para fiscalização TCU

TCU sistematicamente aponta como irregularidade: UST sem padronização, fiscal sem qualificação técnica, atesto sem fundamentação (art. 117 §1º Lei 14.133), critério de medição inconsistente. O EasyNuP modela cada uma dessas exigências como regra executável no domínio — não como item em manual PDF. O órgão que opera o sistema atende essas exigências por desenho, não por treinamento individual.
